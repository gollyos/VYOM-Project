# PHASE 12 OBJECTIVE

Build VYOM's persistent multi-device runtime.

After this phase VYOM should be capable of:

1. Running permitted workloads 24/7
2. Continuing background tasks when desktop UI is closed
3. Recovering safely after crashes/restarts
4. Supporting a dedicated Home Server / Worker Node
5. Supporting optional cloud-hosted Brain/worker deployment
6. Connecting desktop and mobile securely
7. Cross-device task/status sync
8. Cross-device voice commands
9. Remote task creation
10. Remote approval/rejection
11. Remote notifications
12. Device presence awareness
13. Task handoff between nodes
14. Offline queueing
15. Conflict-safe synchronization
16. Health monitoring
17. Automatic bounded recovery
18. Backup/restore
19. Secure device pairing
20. Audit logs across devices
21. Remote "What is VYOM doing?" visibility
22. Reliable scheduled automations while the main desktop window is not open

Do NOT build unrestricted remote desktop access.

VYOM remains user-controlled, permission-based and auditable.

# 1. DISTRIBUTED VYOM ARCHITECTURE

VYOM may run across multiple trusted nodes:

```text
Desktop
Laptop
Mobile
Home Server
Optional Cloud Worker
```

Only one component should coordinate a specific task at a time.

Create explicit concepts:

```text
Brain Coordinator
Execution Node
Client Device
Worker Node
```

A device may have multiple roles.

---

# 2. HOME SERVER / ALWAYS-ON NODE

Create architecture for an always-on VYOM worker.

Possible deployment:

```text
mini PC
home server
NAS-compatible environment
Linux machine
Docker host
```

Responsibilities may include:

* Brain service
* automations
* research jobs
* scheduled workflows
* notifications
* memory/database
* lightweight agents
* background monitoring

Do NOT require the desktop gaming/work PC to remain powered on.

---

# 3. WORKLOAD PLACEMENT

Task Router should decide where a task can run.

Consider:

```text
required tools
required files
device availability
privacy
GPU requirement
browser requirement
local project requirement
latency
cost
```

Example:

Email research
→ Home Server

Compile local Windows project
→ Desktop Node

Mobile notification
→ Mobile Node

GPU-heavy local model
→ capable device only.

---

# 4. NODE OWNERSHIP

Prevent duplicate execution.

Implement task ownership/lease concept:

```text
task_id
node_id
lease_id
acquired_at
expires_at
heartbeat
```

If node dies:

lease expires
→ coordinator decides whether safe retry/handoff is possible.

Consequential tasks require extra duplicate protection.

---

# 5. SAFE TASK HANDOFF

Support:

```text
Desktop loses connection
↓
persist checkpoint
↓
Coordinator evaluates
↓
eligible worker resumes
```

Only if task capabilities are portable.

Example:

Research task:
portable.

Local coding task requiring Desktop project:
not portable unless repository/environment exists on target node.

---

# 6. CHECKPOINTS

Long-running tasks should save checkpoints.

Checkpoint may include:

```text
task state
current plan step
completed tool calls
evidence
pending approval
budget consumed
artifacts
```

Do NOT persist private hidden reasoning.

---

# 7. CRASH RECOVERY

After Brain restart:

```text
load persisted tasks
→ detect previously running tasks
→ inspect evidence
→ determine:
   resume
   retry
   pause
   mark needs review
```

Never blindly repeat consequential external actions.

---

# 8. CIRCUIT BREAKERS

Implement circuit breakers for:

```text
provider failures
tool failures
MCP failures
integration outages
network failures
```

Example:

Gmail fails 5 times
→ temporarily stop Gmail-dependent workflows
→ mark integration degraded
→ notify user

Avoid retry storms.

# 71. COMMAND — PAUSE EVERYTHING

User:

"VYOM pause everything."

Define carefully.

Should:

* pause non-critical autonomous tasks
* pause automations where safe
* stop new background work

Do not abruptly corrupt active file/database operations.

Critical housekeeping may finish safely.

# 72. COMMAND — RESUME

"Resume VYOM."

Resume eligible paused automation/tasks according to policy.

# 78. POWER AWARENESS

For portable devices where supported:

if battery low:

avoid heavy non-essential local work.

Move portable tasks to Home Server where possible.

# 79. NETWORK AWARENESS

If device is on poor network:

defer large transfers.

Do not continually retry large sync operations.
